## 3. Опрос GPIO и прерывания

При опросе программа постоянно читает вход:

```c
while (1)
{
    if (HAL_GPIO_ReadPin(BTN_GPIO_Port, BTN_Pin) == GPIO_PIN_RESET)
    {
        HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
        HAL_Delay(200);
    }
}
```

Это учебный пример, а не надёжная обработка кнопки: при удержании возможно повторное переключение, а задержка не устраняет дребезг.

При использовании прерывания аппаратный блок EXTI обнаруживает выбранный фронт сигнала и формирует запрос IRQ. NVIC управляет разрешением и приоритетами IRQ. Процессор выполняет обработчик, затем возвращается к прерванному коду.

**Концептуальная цепочка:** GPIO → EXTI → NVIC → IRQ-обработчик → HAL callback → основной цикл.

Это функциональная схема, а не электрическая схема конкретной платы.

## 4. EXTI и NVIC в STM32F407

### EXTI

EXTI (External Interrupt/Event Controller) обнаруживает настроенные события. Для GPIO-линий 0–15 номер линии соответствует номеру вывода. Например, для PA5 можно использовать EXTI5. Для одной линии EXTI выбирается один источник GPIO с соответствующим номером — например, PA5 или PB5.

Можно настроить:
- нарастающий фронт (`Rising edge`);
- спадающий фронт (`Falling edge`);
- оба фронта (`Rising/Falling edge`).

Если кнопка подключена между входом и землёй, а вход подтянут вверх, нажатие обычно создаёт спадающий фронт. Всегда сверяйтесь с электрической схемой платы.

### NVIC

NVIC (Nested Vectored Interrupt Controller) — контроллер прерываний ядра Cortex-M4. Он управляет разрешением IRQ и приоритетами.

| Линии EXTI | IRQ-обработчик |
|---|---|
| EXTI0 | `EXTI0_IRQHandler()` |
| EXTI1 | `EXTI1_IRQHandler()` |
| EXTI2 | `EXTI2_IRQHandler()` |
| EXTI3 | `EXTI3_IRQHandler()` |
| EXTI4 | `EXTI4_IRQHandler()` |
| EXTI5–EXTI9 | `EXTI9_5_IRQHandler()` |
| EXTI10–EXTI15 | `EXTI15_10_IRQHandler()` |

## 5. Настройка в STM32CubeIDE

1. Создайте проект для точной модели STM32F407, установленной на вашей плате.
2. Выберите свободный GPIO, физически подключённый к кнопке, или подключите внешнюю кнопку по безопасной схеме.
3. Назначьте вывод режиму EXTI для соответствующей линии.
4. Для кнопки с подтяжкой вверх и замыканием на землю обычно задают `GPIO_MODE_IT_FALLING` и `GPIO_PULLUP`.
5. В разделе NVIC включите соответствующий IRQ. Например, EXTI5 входит в группу `EXTI line[9:5] interrupt`.
6. Сохраните `.ioc` и сгенерируйте код.

CubeMX обычно создаёт настройку GPIO/EXTI, разрешение IRQ в NVIC и обработчик в `stm32f4xx_it.c`. Не дублируйте вручную то, что уже сгенерировано.

## 6. Обработчик IRQ и HAL callback

Для EXTI5 обработчик обычно выглядит так:

```c
void EXTI9_5_IRQHandler(void)
{
    HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_5);
}
```

HAL обрабатывает соответствующий флаг и вызывает пользовательский callback:

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    /* Короткая обработка события */
}
```

Точный вид сгенерированного кода зависит от версии HAL и конфигурации. Проверьте файлы собственного проекта.

## 7. Практический код: событие кнопки

### Шаг 1. Объявить флаг

В `main.c`, в пользовательской секции глобальных переменных:

```c
/* USER CODE BEGIN PV */
volatile uint8_t buttonEvent = 0;
/* USER CODE END PV */
```

Обычно `uint8_t` уже доступен через подключаемые HAL-заголовки. Если нет, добавьте подходящий заголовок.

### Шаг 2. Реализовать callback

В `main.c`, вне `main()`:

```c
/* USER CODE BEGIN 4 */
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == BTN_Pin)
    {
        buttonEvent = 1;
    }
}
/* USER CODE END 4 */
```

`BTN_Pin` — имя, которое должно соответствовать реальной конфигурации CubeMX. Если callback уже существует, добавьте проверку в существующую функцию, не создавайте вторую.

### Шаг 3. Обработать событие в основном цикле

```c
while (1)
{
    /* USER CODE BEGIN 3 */
    if (buttonEvent != 0)
    {
        buttonEvent = 0;
        HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
    }
    /* USER CODE END 3 */
}
```

Обработчик лишь устанавливает флаг; светодиод переключается в основном цикле.

**Ограничение:** флаг объединяет события. Если несколько прерываний произойдут до обработки первого, каждое событие не будет посчитано отдельно. Для подсчёта каждого события может понадобиться счётчик или очередь с корректной синхронизацией.

## 8. Последовательность выполнения

1. Основной цикл выполняет обычный код.
2. На входе появляется выбранный фронт.
3. EXTI фиксирует событие и формирует IRQ.
4. NVIC передаёт управление обработчику, когда это допускают приоритеты и состояние процессора.
5. HAL вызывает `HAL_GPIO_EXTI_Callback()`.
6. Callback устанавливает флаг.
7. После возврата из прерывания основной цикл обнаруживает флаг и переключает светодиод.

## 9. Дребезг кнопки

Механическая кнопка может несколько раз переключать контакт при одном нажатии. В результате одно физическое действие может вызвать несколько прерываний.

Не устраняйте дребезг вызовом `HAL_Delay()` внутри ISR. Это может задерживать выполнение другого кода и нарушать временные требования. В следующих занятиях можно реализовать программную фильтрацию с таймером; возможна также аппаратная фильтрация.

## 10. Практическая работа

### Задание A — кнопка и светодиод
- Создайте проект или продолжите предыдущий.
- Настройте вход в режиме EXTI и включите IRQ в NVIC.
- Реализуйте callback и флаг события.
- Проверьте, что каждое корректно зарегистрированное нажатие переключает светодиод.

### Задание B — отладка
- Поставьте точку останова внутри `HAL_GPIO_EXTI_Callback()`.
- Нажмите кнопку.
- Проверьте значение `GPIO_Pin`.
- Убедитесь, что программа продолжает выполнение после выхода из callback.

### Задание C — полярность фронта
Объясните, почему кнопка с подтяжкой вверх, замыкающая вход на землю, обычно создаёт спадающий фронт при нажатии и нарастающий при отпускании.

### Критерии успешного выполнения
- проект собирается без ошибок;
- выбранный GPIO соответствует реальному подключению;
- callback вызывается при ожидаемом событии;
- студент может объяснить цепочку EXTI → NVIC → обработчик → callback;
- пользовательский код расположен в секциях `USER CODE`.

## 11. Типичные ошибки

| Симптом | Что проверить |
|---|---|
| Callback не вызывается | Режим EXTI, NVIC, номер линии, IRQ-обработчик |
| Callback вызывается несколько раз | Дребезг или шум на входе |
| Программа надолго зависает в ISR | Задержки, блокирующие функции, бесконечные циклы |
| Срабатывает не тот фронт | Электрическую схему и настройку фронта |
| Не работает кнопка | Физическое подключение и назначение вывода |
| Теряются события | Флаг не хранит число событий; нужен счётчик или очередь |
| Выбран неверный IRQ | EXTI5–9 используют общий `EXTI9_5_IRQn`; EXTI10–15 — `EXTI15_10_IRQn` |

## 12. Контрольные вопросы

1. Какова основная задача EXTI?
2. За что отвечает NVIC?
3. Какой обработчик используется для EXTI5 на STM32F407?
4. Почему не следует вызывать `HAL_Delay()` внутри callback прерывания?
5. Что даёт `volatile`, а чего он не гарантирует?

### Ответы для преподавателя

1. Обнаружение настроенных внешних событий и формирование запросов.
2. Разрешение IRQ, управление приоритетами и обработкой прерываний.
3. `EXTI9_5_IRQHandler()`.
4. Задержка может блокировать обработку другого кода и нарушать временные требования.
5. `volatile` заставляет компилятор учитывать внешние изменения переменной, но не обеспечивает полноценную синхронизацию и не предотвращает потерю событий.
6. Из-за механического дребезга контактов.

## 13. Выводы

Студент освоил цепочку обработки внешнего события: **GPIO → EXTI → NVIC → IRQ-обработчик → HAL callback → основной цикл**.

Главные инженерные правила:
- обработчик должен быть коротким;
- сложную работу следует выполнять вне ISR;
- `volatile` не заменяет механизмы синхронизации;
- дребезг нужно обрабатывать отдельно;
- конфигурация должна соответствовать реальной плате.
