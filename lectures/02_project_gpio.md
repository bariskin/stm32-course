## 3. Что такое GPIO

GPIO (General-Purpose Input/Output) — универсальный цифровой вывод микроконтроллера. В зависимости от конфигурации он может считывать цифровой уровень, выдавать уровень или выполнять альтернативную функцию периферийного блока.

GPIO не предназначен для непосредственного питания произвольной нагрузки: учитывайте допустимый ток вывода и используйте драйвер, если это требуется.

### Основные режимы

- **Input** — чтение цифрового уровня.
- **Output Push-Pull** — выход активно формирует высокий и низкий уровни.
- **Output Open-Drain** — выход может тянуть линию вниз; высокий уровень обычно обеспечивается подтяжкой.
- **Alternate Function** — вывод подключается к периферии, например UART, SPI, I2C или таймеру.
- **Analog** — цифровые буферы отключаются для аналогового использования.

Дополнительные параметры: подтяжка No Pull, Pull-up, Pull-down, скорость переключения и выходной тип.

**GPIO speed** — это настройка характеристик переключения выходного драйвера, а не частота выполнения C-кода. Выбирайте минимально достаточное значение с учётом сигнала и электромагнитных помех.

## 4. Создание проекта в STM32CubeIDE

1. Запустите STM32CubeIDE.
2. Выберите создание нового STM32-проекта.
3. Выберите точную модель микроконтроллера или поддерживаемую плату.
4. Назовите проект, например gpio_basics.
5. Откройте файл конфигурации .ioc.
6. В Pinout & Configuration назначьте свободный вывод режиму GPIO Output.
7. В GPIO Configuration выберите подходящие параметры, например Output Push-Pull, No Pull и низкую/умеренную скорость.
8. Сохраните .ioc и сгенерируйте код.

CubeMX формирует начальную конфигурацию GPIO и HAL. Проект обычно содержит main.c, gpio.c, main.h и другие файлы в зависимости от настроек.

## 5. Что делает сгенерированный код

В main() обычно выполняется инициализация HAL, системных тактовых настроек и выбранной периферии:

~~~c
HAL_Init();
SystemClock_Config();
MX_GPIO_Init();
~~~

Конкретная последовательность определяется шаблоном проекта. Изучите порядок, который сгенерировала IDE.

Упрощённый пример настройки одного выхода:

~~~c
static void MX_GPIO_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStruct = {0};

    __HAL_RCC_GPIOA_CLK_ENABLE();

    HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_RESET);

    GPIO_InitStruct.Pin = GPIO_PIN_5;
    GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;
    GPIO_InitStruct.Pull = GPIO_NOPULL;
    GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
    HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);
}
~~~

Это иллюстративный фрагмент, а не готовая конфигурация для любой платы. Он подходит только если GPIOA и PA5 доступны и не нужны другой периферии. В проекте CubeMX предпочтительно менять настройки через .ioc, чтобы не потерять конфигурацию при регенерации.

## 6. Управление GPIO через HAL

### Установить высокий или низкий уровень

~~~c
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET);
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_RESET);
~~~

GPIO_PIN_SET задаёт логическую 1 на настроенном выходе, GPIO_PIN_RESET — логический 0.

### Инвертировать выход

~~~c
HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
~~~

Функция переключает выход в противоположное состояние. Она удобна для учебного мигания светодиодом, но не заменяет аппаратный таймер, когда нужна точная временная характеристика.

### Прочитать вход

~~~c
GPIO_PinState state = HAL_GPIO_ReadPin(GPIOC, GPIO_PIN_13);

if (state == GPIO_PIN_SET)
{
    /* На входе распознан высокий логический уровень */
}
~~~

Полярность кнопки зависит от схемы. При кнопке между входом и GND с подтяжкой вверх нажатие обычно читается как GPIO_PIN_RESET.

## 7. Учебное мигание светодиодом

После настройки выхода поместите фрагмент в основной цикл, заменив порт и вывод на имена из CubeMX:

~~~c
while (1)
{
    HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
    HAL_Delay(500);
}
~~~

LED_GPIO_Port и LED_Pin — пример именования. Используйте определения из своего main.h или задайте имена в CubeMX. Если светодиод активен низким уровнем, видимое поведение может быть инвертировано.

HAL_Delay() подходит для первого знакомства, но блокирует текущий поток на заданное время. В проектах с несколькими задачами или точными временными требованиями используйте таймеры или планировщик RTOS.

### Задание A — создать проект

- Замените HAL_GPIO_TogglePin() парой вызовов HAL_GPIO_WritePin().
- Измените интервал.
- Объясните, почему длительный HAL_Delay() затрудняет выполнение других задач в цикле.

### Критерии успешного выполнения
- проект собирается без ошибок;
- GPIO настроен через .ioc;
- пользовательский код находится в предназначенных для него секциях;
- студент может объяснить режим, подтяжку и скорость;
- выбранный вывод соответствует реальной плате.

## 9. Типичные ошибки

| Проблема | Что проверить |
|---|---|
| Вывод не меняет уровень | Тактовый сигнал GPIO, порт и pin |
| Проект не собирается | Имена портов и выводов, объявления, дубликаты функций |
| Светодиод не светится | Схему платы, полярность, ток и выбранный вывод |
| После регенерации пропал код | Пользовательские секции USER CODE |
| Вывод работает не как GPIO | Не назначена ли альтернативная функция |
| Внешняя нагрузка не работает | Допустимый ток и необходимость драйверного каскада |
| Кнопка читается наоборот | Схему и подтяжку входа |

## 10. Контрольные вопросы

1. Что означает GPIO?
2. Чем отличаются Input, Output Push-Pull, Open-Drain и Alternate Function?
3. Зачем нужна подтяжка входа?
4. Что делают HAL_GPIO_WritePin() и HAL_GPIO_TogglePin()?
5. Почему GPIO speed — не то же самое, что частота выполнения программы?
6. Почему нельзя считать, что PA5 подключён к светодиоду на любой плате STM32F407?
7. Чем неудобен HAL_Delay() в сложном приложении?

### Краткие ответы для преподавателя

1. General-Purpose Input/Output — универсальный цифровой ввод/вывод.
2. Режимы определяют чтение входа, активное управление выходом, выход с открытым стоком или передачу вывода периферийному блоку.
3. Подтяжка задаёт определённый уровень, когда внешний источник не управляет линией.
4. Первая задаёт уровень, вторая переключает его.
5. GPIO speed определяет характеристики переключения выходного драйвера, а не скорость выполнения инструкций.
6. Разводка зависит от конкретной платы.
7. Задержка блокирует текущий поток выполнения.
